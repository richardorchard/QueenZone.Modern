# Forum anti-spam defenses

Automated bulk-signup bots register an account and post within seconds, usually carrying a link.
This note records the current defenses in `ForumPostWriteService` and `ForumPostRateLimiter`, and
why they're shaped the way they are.

## 1. Per-member rate limit

`ForumPostRateLimiter` (`src/QueenZone.Web/Forum/ForumPostRateLimiter.cs`) caps every member at
`MaxPostsPerMinute = 5` over a 1-minute sliding window, checked before a topic/reply write is
attempted. It fails closed on a data-store error (treats the write as not-allowed rather than
silently permitting it). This throttles volume; it does nothing about content or account age.

## 2. New-account auto-suspend heuristic

`ForumPostWriteService.FlagIfLikelySpamAsync` runs *after* a topic or reply is successfully
created (the post itself is never blocked pre-write). Within `SpamCandidateWindow` (60 seconds)
of the account's `CreatedAt`, either of these is treated as a bulk-signup-bot signature and
auto-suspends the member:

- The post body contains a link (`https?://|www\.`), **or**
- The registration email matches `AutoGeneratedFreemailPattern` — a short word, an underscore,
  and a 12-20 character hex run, on a Microsoft freemail domain (`outlook.com`, `hotmail.com`,
  `live.com`, `msn.com`), e.g. `outlook_D2B04D13FE864466@outlook.com`.

Either signal alone is enough once the account is that new; there's no case where both must
hold. A genuine member essentially never hits either condition within 60 seconds of registering,
and never registers with a generator-shaped address at all, so the email check is safe standing
alone even when the post itself contains no link.

On trigger: the member is suspended with `SuspendedByAdminEmail = ForumPostWriteService.AutoModeratorEmail`
(`automod@queenzone.internal`, distinct from a human moderator's email in the audit trail), and
all their forum content is hidden via `IForumWriteRepository.HideAuthorForumContentAsync`. The
post row itself is not deleted — a false positive is recoverable through normal admin
reinstatement, the same path as an unsuspend after a manual moderator action.

`trustedSystemAuthor` posts (the system-authored News-forum topic opener, see
[ADR 0016](../decisions/0016-news-forum-topic-on-first-publish.md)) skip this check entirely,
since that path always contains a URL by design.

### Why this pattern and not a broader "weird email" heuristic

The email regex is deliberately narrow — this exact `word_HEXCHARS@msdomain` shape only — rather
than a general randomness/entropy heuristic. It was added after a live spam account
(`outlook_D2B04D13FE864466@outlook.com`) posted without a link and so evaded the link-based
check. A broader heuristic would catch more bot patterns but risks flagging real members whose
addresses are merely unusual; this repo has no prior email-quality validation at all (see below),
so the narrow, evidence-based pattern was chosen to keep false positives at effectively zero.

## 3. No email validation at registration

`MemberAccountService.RegisterAsync` (`src/QueenZone.Web/Member/MemberAccountService.cs`) only
checks for a duplicate email; it does not reject on shape, domain, or disposable-address lists.
The only email format validation elsewhere in the codebase is `HelpRequestService.ValidateEmail`,
which is RFC-shape parsing for the Help/contact form and unrelated to registration or forum
posting. Registration-time rejection of generator-shaped addresses was considered and deferred:
flagging behaviorally (post-write, combined with the age window) was judged lower-risk than
blocking sign-up outright, since it keeps the account recoverable if the pattern ever produces a
false positive.

## Tests

`tests/QueenZone.Web.Tests/ForumPostWriteServiceTests.cs` covers:

- Link + new account → auto-suspend.
- Link + old account → no action.
- New account, no link, ordinary email → no action.
- New account, no link, generator-shaped email → auto-suspend.
- Old account, generator-shaped email → no action (age gate still applies).
- New account, merely unusual (but not generator-shaped) email → no action.
- `trustedSystemAuthor` bypasses the check even with a new account and a link.
