Queenzone Design System · Addendum

Forms & admin controls

The public archive is editorial. The admin is a workroom — the same tokens, spoken more quietly. This chapter fixes the controls the core system never specified: labels, selects, checkboxes, file pickers, validation, data tables, and how every one of them behaves on a phone.

01 · Principles

A quieter skin, the same system

Admin screens use the identical colour, type and spacing tokens as the public archive, with three deliberate reductions: no display type below page titles, no accent colour except where it carries meaning, and no editorial flourish — no crest watermarks, no dark bands, no scrims.

Never a browser default

Every native control is restyled. An unstyled <input type="file"> or 22px submit button breaks the archive's promise of care.

One primary per view

A screen has a single filled button — Save, Publish, Post. Everything else is secondary, ghost or a link.

Accent by meaning

Blue for focus and links. Burgundy for destructive and error. Gold never appears in admin.

Editing is content work

Fields holding published prose are set at the reading measure — 680px — not stretched to the viewport.

02 · Buttons

Sizes and variants

Admin standardises on the DS md size — 12/24 padding, rendering 43px tall. Use sm (8/16, 34px) inside dense table rows and lg (16/34, 51px) only for a full-width mobile submit. The DS Button component supplies all five variants; do not hand-roll a sixth.

Grouping

  • Gap between buttons in a group: 12px. Never rely on source whitespace.
  • Order left to right: primary, secondary, then ghost/link. Destructive sits apart, right-aligned or separated by 32px.
  • Never mix a button and a bare text link in the same group — promote the link to ghost.
  • Full width only below 720px, and only for the primary.
03 · Text fields

Inputs, textareas, selects

One field per row. Width is set by the content it holds, not by the container — a subject line takes the full column, a date takes 180px. Fields are never left at their native browser width.

Rules

  • Labels sit above the field, never beside it — the inline Subject ▭ pattern in the current forum form is wrong at every width.
  • Placeholders are examples, never substitutes for a label.
  • Selects use the same shell as inputs with a 5px chevron 18px from the right edge.
  • Field column caps at 680px. Beyond that, add a second column — don't stretch.
04 · Choice controls

Checkboxes, radios, toggles

The whole row is the target — control, label and description — never the 13px box alone. Use a checkbox for independent options, radios for one-of-few, and a toggle only where the change takes effect immediately.

05 · File & image

Upload and gallery picker

The native Choose file control is always hidden. In its place: a dropzone showing the current image, the two ways to supply one, and the constraints stated before the user picks — not after they fail.

Q
Drop an image here, or
Choose file Choose from gallery
JPEG, PNG or WebP · max 10 MB · cropped to the 3:2 news-card frame. Gallery originals are never modified.
Uploading · 64%
  • Placeholder state uses the crest-on-black 3:2 frame, with the caption "No article image yet — listings will use this placeholder."
  • Once an image exists, the dropzone becomes the thumbnail plus Replace and Remove ghost buttons.
  • Constraints (format, size, crop) live under the control, not in an error dialog.
  • On mobile the two columns stack; the preview goes full width above the buttons.

Rhythm and structure

  • Fieldsets carry an eyebrow legend and a hairline: Content, Image, Publication, Advanced.
  • Rarely-used settings sit in a collapsed Advanced group, closed by default.
  • Save / Cancel / Preview live in one group with 12px gaps — the current mix of a button, a bare pipe and two links is not a pattern.
  • Unsaved changes: a warning on navigation away, never a silent loss.
08 · Data tables

Rules

  • Title is the only link in the row — it opens the editor. Drop the separate "Edit / Preview" text-link pair.
  • Maximum three visible actions; anything further goes in an overflow menu.
  • Delete is last, separated, and burgundy on hover only.
  • Filters and count sit in a bar above the header row, never floating above the page title.
09 · Destructive actions

Deleting from an archive

This archive exists because material was nearly lost once. Deletion is therefore always confirmed, always names the item, and — wherever the data model allows — is a soft delete that can be restored.

Delete this article?

"Barry Mitchell, Early Queen Bassist, Has Died" will be removed from the public archive and moved to the trash for 30 days.

Irreversible deletions — purging trash, removing a member's post history — additionally require typing the item's name. Bulk deletion always states the count.

10 · Mobile

Below 720px

Admin is used from a phone — moderating a thread on a train, approving a photo submission. Every control grows to a 44px minimum target, fields go to 16px type so iOS does not zoom, and the listing table stops being a table.
